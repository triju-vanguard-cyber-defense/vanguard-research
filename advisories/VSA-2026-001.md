\# Vanguard Security Advisory: VSA-2026-001

\*\*Title:\*\* Cascading Delegation Poisoning \& Action-Space Overreach in Multi-Agent Orchestrations  

\*\*Target Framework:\*\* CrewAI / Multi-Agent Architectures  

\*\*Author:\*\* Triju Das, Vanguard Cyber Defense  

\*\*Classification:\*\* OWASP LLM01 (Prompt Injection) / OWASP LLM08 (Excessive Agency) / MITRE ATLAS AML.T0043  

\*\*Status:\*\* Published Research / Educational Reference  



\---



\## 1. Executive Summary

In autonomous multi-agent environments utilizing collaborative task delegation, cross-agent communication channels often lack strict trust boundaries. When an upstream ingestion agent processes untrusted external context, adversarial injection payloads can alter the agent's task assignment logic. In configurations where downstream sub-agents possess privileged execution tools (such as database query executors or API integrations), the downstream agent treats the malicious delegated instruction as trusted internal state, resulting in unauthorized action-space execution.



\---



\## 2. Technical Vulnerability Analysis



\### A. Architectural Pattern

Consider a standard two-agent workflow:

1\. \*\*Agent A (Ingestion Agent):\*\* Fetches and summarizes external data (e.g., web search results, support tickets). Configured with `allow\_delegation=True`.

2\. \*\*Agent B (Execution Agent):\*\* Equipped with external API or database tools to perform operational tasks.



\### B. The Exploitation Mechanism

1\. \*\*Untrusted Ingestion:\*\* Agent A ingests an external document containing an indirect prompt injection payload disguised as standard data.

2\. \*\*Instruction Hijacking:\*\* The payload directs Agent A to delegate a high-priority sub-task to Agent B with altered operational parameters.

3\. \*\*Implicit Trust Failure:\*\* Agent B evaluates the delegated task as coming from an internal coordinator, bypassing basic user-input validation.

4\. \*\*Action-Space Overreach:\*\* Agent B invokes its associated tool functions with the adversary-controlled parameters.



\---



\## 3. Threat Modeling \& Impact

\- \*\*Confidentiality:\*\* Unauthorized exfiltration of system prompt configurations, internal tool schemas, or database tables.

\- \*\*Integrity:\*\* State corruption in connected systems if execution tools allow mutation (write, update, delete) without human confirmation gates.

\- \*\*Availability:\*\* Denial-of-service through recursive delegation loops or resource exhaustion.



\---



\## 4. Remediation \& Hardening Guidelines



\### 1. Implement Strict Action-Space Least Privilege

\- Restrict execution tools: Agents handling external data should never have write permissions or administrative API access.

\- Use explicit Pydantic parameter schemas with strict regex and type constraints on all tool inputs.



\### 2. Segregate Agent Trust Domains

\- Disable `allow\_delegation=True` unless explicitly required.

\- When delegation is necessary, sanitize inter-agent messages through an intermediate guardrail evaluator before task assignment.



\### 3. Enforce Human-in-the-Loop (HITL) for Privileged Actions

\- Mandate human confirmation tokens before executing any high-impact tool action (e.g., database writes, bulk communication, or configuration alterations).



\### 4. Explicit Context Boundaries

\- Wrap untrusted ingested content in distinct boundary delimiters (e.g., `<untrusted\_payload> ... </untrusted\_payload>`) and instruct model policy to treat enclosed text strictly as passive data.
