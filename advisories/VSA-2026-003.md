# Vanguard Security Advisory: VSA-2026-003

**Title:** Unauthenticated PS1 Completion Markers in Terminal Metadata Parser
**Target Framework:** OpenHands (All Hands AI) / `openhands-tools` (software-agent-sdk)
**Author:** Triju Das, Vanguard Cyber Defense
**Classification:** CWE-345 (Insufficient Verification of Data Authenticity)
**Status:** Disclosed to vendor via GitHub Private Security Advisory (September 12, 2026) — Awaiting triage. Advisory ID: GHSA-m8ch-x6m8-mjw3. GitHub displayed Moderate (4.0/10) from the reporter-supplied CVSS vector; this is not an independent vendor confirmation.

---

## 1. Executive Summary

During an architectural source-code audit of `openhands-tools` (software-agent-sdk, package version 1.47.0), Vanguard Cyber Defense identified that terminal completion metadata is parsed from a **fixed, publicly-known marker pair** in raw output, with no session nonce or origin check.

**What was demonstrated**

1. **Parser accepts forged JSON.** `CmdOutputMetadata.matches_ps1_metadata()` / `from_ps1_match()` accepted a constructed `###PS1JSON###` … `###PS1END###` block and returned attacker-chosen `exit_code`, `hostname`, and `working_dir`.
2. **Live Windows PowerShell did not trust that block as final metadata.** On a real `WindowsTerminal` session, a command that printed a forged marker and then set `$LASTEXITCODE` via `cmd /c exit 1` reported the **real** exit code (`1`), real username, real hostname (`OPEN-CLOSE`), and real working directory. The authentic prompt suffix won.

**What was not demonstrated**

- No live override of exit code, hostname, or cwd on Windows PowerShell.
- No bash/tmux end-to-end test.
- No test where a forged block is the **final** marker with no authentic suffix after it.

Issue B below is therefore a **code-path hypothesis**, not a confirmed live impact.

---

## 2. Technical Breakdown

### Issue A: Parser accepts unauthenticated PS1 JSON (confirmed)

* **Location:** `openhands-tools/openhands/tools/terminal/metadata.py`, `openhands-tools/openhands/tools/terminal/constants.py`
* **Finding:** Markers are static strings:

  `CMD_OUTPUT_PS1_BEGIN = "\n###PS1JSON###\n"`  
  `CMD_OUTPUT_PS1_END = "\n###PS1END###"`

  Any text between these markers that parses as JSON is accepted. There is no session-specific nonce or signature.

### Issue B: Downstream trust of matched markers (not confirmed live on Windows)

* **Location:** `openhands-tools/openhands/tools/terminal/terminal/terminal_session.py`
* **Finding:** Session code uses PS1 matches as command boundaries. In isolation, that could misattribute metadata if a forged block were treated as the authoritative match.
* **Live Windows result (2026-09-17):** A forged block printed from PowerShell did **not** become final metadata. Control `cmd /c exit 7` reported exit `7` with real host/cwd. Forged marker then `cmd /c exit 1` reported exit `1` with the same real host/cwd/PID. Fake cwd / fake host: false.

Windows PowerShell does emit the same `###PS1JSON###` suffix. The live session appears to use a **later authentic prompt suffix**, so a naive in-stream forgery was not sufficient on this backend.

---

## 3. Recommended Hardening Guidelines

1. **Session-Specific Nonce:** Include a random, per-session secret in the marker pattern; reject matches missing that nonce.
2. **Independent Verification:** Cross-check marker-derived completion against PTY/subprocess state, not in-stream text alone.
3. **Data/Control Separation:** Do not treat command stdout as a trusted control channel.
