# Vanguard Security Advisory: VSA-2026-003

**Title:** Unauthenticated PS1 Completion Markers Enable Forged Command Metadata in Terminal Tool
**Target Framework:** OpenHands (All Hands AI) / `openhands-tools` (software-agent-sdk)
**Author:** Triju Das, Vanguard Cyber Defense
**Classification:** CWE-345 (Insufficient Verification of Data Authenticity), OWASP LLM08 (Excessive Agency)
**Status:** Disclosed to vendor via GitHub Private Security Advisory (September 12, 2026) — Awaiting triage. Advisory ID: GHSA-m8ch-x6m8-mjw3, assessed by GitHub as Moderate (4.0/10).

---

## 1. Executive Summary

During an architectural source-code audit of `openhands-tools` (part of the `software-agent-sdk` repository, package version 1.47.0), Vanguard Cyber Defense identified an unauthenticated trust boundary between shell-generated control data and untrusted command output:

1. **Unauthenticated Completion Markers:** The terminal tool determines a bash command's exit code, process ID, username, hostname, and working directory by regex-matching a fixed, publicly-known marker pair (`###PS1JSON###` / `###PS1END###`) in raw terminal output, then parsing the enclosed text as JSON — with no session-specific nonce, signature, or other verification that the content actually originated from the shell.
2. **Data/Control-Plane Confusion:** Because the markers are scanned for anywhere in the output stream, any content a command *displays* (e.g. `cat` on an untrusted file, output from a compromised dependency, scraped web content) can inject a complete, well-formed metadata block that is accepted as authoritative.
3. **Acknowledged but Unaddressed:** The regex already special-cases "corruption scenarios where concurrent output causes nested markers," showing the maintainers are aware look-alike content can appear in output — but this hardens only the matching logic, not the underlying trust assumption.

---

## 2. Technical Breakdown

### Issue A: Unauthenticated PS1 Completion Marker Injection

* **Location:** `openhands-tools/openhands/tools/terminal/metadata.py`, `openhands-tools/openhands/tools/terminal/constants.py`
* **Finding:** Markers are static strings — `CMD_OUTPUT_PS1_BEGIN = "\n###PS1JSON###\n"` and `CMD_OUTPUT_PS1_END = "\n###PS1END###"`. `CmdOutputMetadata.matches_ps1_metadata()` accepts any text between these markers that parses as valid JSON, with no verification of origin. `TerminalSession._get_command_output()` uses these matches to determine command boundaries and metadata surfaced directly to the agent.

### Issue B: Downstream Trust of Forged Metadata

* **Location:** `openhands-tools/openhands/tools/terminal/terminal/terminal_session.py`
* **Finding:** `_combine_outputs_between_matches()` treats matched markers as authoritative command boundaries, meaning forged markers embedded in command output can misattribute exit codes, truncate/split real output, or misreport working directory, username, and hostname to the agent.

---

## 3. Recommended Hardening Guidelines

1. **Session-Specific Nonce:** Include a random, per-session secret (generated at terminal session initialization, never derivable from anything the shell would echo verbatim) as part of the marker pattern, and reject matches missing the correct nonce.
2. **Independent Verification:** Cross-check marker-derived completion status against an independent signal (e.g., a `wait()`/`poll()` on the underlying PTY/subprocess) rather than trusting in-stream text alone.
3. **Data/Control Separation:** Treat all terminal output as untrusted data by default; require explicit, structurally-distinct signaling (outside the regular output stream) for control metadata.
